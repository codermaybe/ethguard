# T10.7 local replication report

Status: **local replication only** (2026-10-23). A fresh clone at the same
commit re-executed the T10.6 manifest without contacting Chainlist. This is not
an external independent-runner review and does not satisfy T10.7's external
acceptance; it establishes local repeatability and provides a difference
classification.

## Method

- T10.6 manifest: `01M5ME05WRGF9QN8RTPAD4HHZ9`,
  sha256 `1d63f7773866d56d398d199b399ec3c83f1d1e1c33c2a9a4d793a4587c5e93e1`,
  source commit `63d5ac7e91b1184e9b1d83653201eaf73e21d81d`.
- Fresh clone: `git clone <local-repository>` then checkout
  `63d5ac7e91b1184e9b1d83653201eaf73e21d81d`; no worktree files, environment
  overrides, or manual edits were used.
- Command: `go run ./cmd/livecanary rerun -manifest <T10.6 manifest> -out
  <recheck>/report.json`.
- `rerun` parses the manifest, executes only its fixed 12-member basis, and
  never re-acquires Chainlist. The report keeps the original run_id and
  manifest digest.
- Verification: copied the original manifest and registry into the recheck
  directory and ran `livecanary verify -dir <recheck>`; all digest, run_id,
  plan, and registry bindings passed.

## Findings

- Local replication is deterministic at the contract level: same manifest and
  same registry, same expected statuses/values/references/invariants.

- The fresh clone had no access to the author's working tree or uncommitted
  changes, but it ran on the same host. External workflow/repository execution
  remains unperformed because no GitHub API credential was available for
